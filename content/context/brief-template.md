# Content brief SOP + checklist (for Alejandra's approval)

Every SEO content task (Optimize or Rewrite) produces a one-page brief in ENGLISH that Alejandra approves BEFORE the article is written or published. Even when the full text already exists, the brief explains the plan. This file is the authoritative checklist: a brief is not done until every applicable item below is satisfied. It reflects every correction Alejandra has given across the AI Virtual Assistants and Tenant Credit Check briefs (July 2026).

Related: [[project_leasey_content]], [[feedback_content_brief_keyword_section]], [[reference_clusterizacion_sheet]]. Persuasion layer on top of this: [[feedback_persuasion_human_nature_lens]].

## Hard rules (never skip)

1. **One focus keyword, declared explicitly, and it gates the rest.** Choose ONE focus keyword for the whole article. On an Optimize job it MUST come from the keywords the page already ranks for, and it must be the one that best fits the existing content so it does not force a rewrite. Declare it on its own, with volume, current position, and intent, plus a one-line rationale. Then list the SECONDARY keywords separately (never blur the two). Alejandra approves the focus keyword before anything else proceeds.

2. **Top-3 Google analysis before proposing headings.** Search the focus keyword. For positions 1, 2, and 3 record: URL, format, word count, their H1/H2/H3, the angles they cover, their sources (or lack of), and their weaknesses. Close with a short "opportunities for Leasey" list. This analysis lives inside the brief so it can be reviewed before the article is written.

3. **Propose the headings, written out.** Based on the top-3 analysis, write the actual H1 and every H2/H3 (real text, not "we will create the H1"), with one line on what each section covers. On an Optimize job, list every CURRENT H2/H3 one by one (kept verbatim) and mark exactly where new blocks (table, FAQ) are inserted.

4. **Meta title <= 55 characters**, carrying the focus keyword, with the character count shown. **Meta description <= 155 characters**, focus keyword in the first sentence, count shown. Never propose keeping a title/description that breaks these limits.

5. **Every figure has a source, and the source is the specific resource URL** (deep link to the exact page or report), never a domain home page. Map each stat -> its exact URL. If a figure cannot be sourced, it is removed or corrected, not published. No `[VERIFY]` may remain in a finished brief: resolve it with the real value + source, or delete the claim.

6. **Author is real** (Carlos Leal for Compliance-pillar pieces, Juan Leal for product/Agent pieces), with an author box and link to /author/<slug> + LinkedIn.

7. **Style guardrails**: British English, Oxford comma, zero em-dashes, "Leasey.AI" capitalisation, active voice, no keyword stuffing, no AI-tell words (see [[ai-tells-do-not-use]]).

## Checklist for the new / rewritten blocks

8. **Intro rules**: first paragraph answers the search intent directly, max 3 lines, zero links.
9. **Paragraph rules**: max 4 lines, short sentences, one idea per paragraph, active voice.
10. **Bold rules**: bold only the key phrase a scanner needs (concept or figure), never whole sentences; max 2-3 per H2.
11. **Image specs**: state which images, where they go, the alt text, and format (WebP, max dimensions).
12. **Length**: non-pillar articles target 800-1,000 words. The length rule does NOT apply to long pillars that already hold many ranking keywords (adding to them, not trimming).
13. **Cluster interlinking**: name 2-3 real sibling articles this piece links OUT to, plus which pages link IN, plus the product interlink to a feature page and /get-started/. Pull real slugs from the cluster (see [[reference_clusterizacion_sheet]]); never invent a slug.

## Extra sections required on an OPTIMIZE (add-only) job

14. **Strategy = protect + add.** Protect every section that carries a ranking keyword (delete or reorder nothing that holds copy). Add: a comparison table above the fold for "vs" intent, an expanded FAQ for the question keywords sitting at positions ~30-98, and E-E-A-T signals (real author + sourced figures). Publish, measure 30 days, only then execute the redirects so their authority flows into a page already climbing.

15. **Keywords closest to page 1 get a targeted plan.** Identify the ranking keywords nearest the top 20 (roughly pos 15-26) and say, per keyword, which existing section reinforces it. Do not treat the 62 as one undifferentiated block.

16. **Section -> keyword map + figure-by-figure corrections.**
    - Map each current H2/H3 -> the keyword(s) it holds, so positions are protected.
    - List invented/vague figures change by change: what is removed, what is kept, and the source URL for each kept figure.
    - **FAQ**: expand well beyond a handful. Each FAQ H3 is an exact-match of a real question keyword currently ranking (with volume + position), chosen because the SERP shows a People-Also-Ask box. Justify why each question is included.
    - **Comparison table**: declare the full structure (every row and column) and the source for each cell; any price cell links to a live pricing page, and any unknown cell reads "varies by provider", never an invented number.

## Standard brief sections (order)

Header (Page, URL, Work type, Pillar, Author, Date, cluster, GA4/GSC visits, ranking-keyword count, consolidations) -> Strategy -> Focus keyword -> Secondary keywords -> Top-3 analysis -> Meta (title/description/H1) -> Heading structure + section->keyword map -> Comparison table structure (if any) -> FAQ -> Figures to correct -> Data -> source URL map -> Cluster interlinking -> Writing rules (intro/paragraph/bold/images/length) -> Guardrails.

Deliver in English, section headers bold only, URLs as live hyperlinks, no `[VERIFY]` left unresolved. See also the general content quality rules in [[content-quality-rules]] (Notion, mirrored here).
